# DECISIONS.md — decisions made while implementing TASK_PLAN.md

Per `TASK_PLAN.md` §0.1 rules 2 and 10, unrelated defects and ambiguous choices
are recorded here instead of being silently changed or blocking work.

## M0-01 — Scaffolding, settings, logging

- **Legacy admin commands moved, not refactored.** `main.py` had to become a
  thin entrypoint, so the four legacy command handlers (`/maintenance`, `/list`,
  `/profile_of_user`, `/ban`, `/unban`, `/banned_list`) were lifted verbatim out
  of `main.py` into `handlers/legacy_commands.py` and registered through
  `register_all_handlers`. This is a **path-only** change: behavior (including
  bug **B1**, the ineffective `/maintenance` toggle) is intentionally preserved
  and will be fixed in M0-05 when the handlers are ported onto `app.services`.
- **`app.settings` field names are snake_case.** pydantic-settings maps env vars
  case-insensitively, so `BOT_TOKEN`, `VPN_TOKEN`, `OWNER_IDS`, `DATABASE_URL`,
  etc. all resolve to their lowercase attributes. This matches the accessor
  names used elsewhere in the plan (`settings.timezone`, `settings.database_url`).
- **Secret masking threshold.** `SecretMaskingFilter` only masks secrets of at
  least 8 characters, to avoid replacing ordinary short strings with `***`.
  Real Telegram/panel tokens are always far longer, so this does not weaken the
  guarantee.
- **Legacy top-level modules are excluded from the gate for now.** `config.py`,
  `loads.py`, `middlewares.py`, `utils.py`, and the top-level `handlers/`
  package still carry many pre-existing defects; they are ported and deleted in
  later M0 tasks. To keep M0-01's gate meaningful, `pyproject.toml` marks them
  `ignore_errors` for mypy. They are intentionally left type-unclean until the
  tasks that own them port the code.
- **`mypy` stays installable via `py3xui`.** `py3xui` declares `mypy` as a
  runtime dependency, so moving `mypy` to `requirements-dev.txt` still works —
  it arrives transitively at runtime. The explicit pin only guarantees the dev
  version.

## M0-02 — Database layer

- **Naive UTC everywhere (`base.utcnow()`).** SQLite has no native timezone-aware
  timestamp type and drops `tzinfo` on read, so a value stored as aware came back
  naive and compared unequal to a freshly built aware value. To keep reads and
  writes symmetric all timestamps are stored naive-but-UTC via
  `app.db.base.utcnow()`; callers that need tz-aware values localize on use.
- **Statuses are `String` columns, `StrEnum` is the source of truth.** The enums
  in `models.py` are Python-side; the DB stores plain text. This keeps the schema
  migration-free when a status list grows, avoids vendor-specific enum DDL, and
  still gives typed access in code. Validation happens at the repository/service
  boundary rather than in the database.
- **Payment "one active payment per user" is a partial unique index.**
  `CREATE UNIQUE INDEX ... ON payments(user_tg_id) WHERE status IN
  ('created','submitted')` (`sqlite_where=`). A plain unique constraint would
  also block historical `approved`/`rejected` rows, which must be allowed to
  accumulate; the partial index enforces the invariant ("at most one *open*
  payment") directly in the DB so it holds even under races.
- **Alembic runs in batch mode (`render_as_batch=True`).** SQLite cannot
  `ALTER` most column properties; batch mode recreates the table to apply
  changes. Enabling it globally means the autogenerated `0001_initial` and all
  future migrations stay SQLite-safe without hand-editing.
- **`fileConfig(..., disable_existing_loggers=False)` in `migrations/env.py`.**
  Alembic's default logging config disabled every already-configured logger,
  which silently muted the application's own loggers whenever a migration ran
  (e.g. at startup). Rerunning `fileConfig` with `disable_existing_loggers=False`
  makes migration logging additive and preserves app logging.
- **Startup migration runs off the event loop (`asyncio.to_thread`).** The async
  Alembic `env.py` calls `asyncio.run()` internally, which raises inside an
  already-running loop. The programmatic runner (`app/db/migrate.py`) is invoked
  from `app/app.py` via `asyncio.to_thread(upgrade_head)`, giving the migration
  its own loop on a worker thread.
- **`path_separator = os` in `alembic.ini`.** Silences the Python 3.12
  `Config.get_main_option` deprecation warning about the path separator when
  resolving `script_location`.
- **`render_item` hook auto-imports `JSONText`.** Autogenerated migrations that
  reference our custom `JSONText` column type need the import injected into the
  template; the `render_item` hook adds `from app.db.base import JSONText` so
  future `--autogenerate` revisions are importable without manual edits.
- **`BroadcastJob.text` is aliased `sa_text`.** The attribute name shadows
  SQLAlchemy's `sqlalchemy.text()` helper inside the module; the model imports it
  as `sa_text` to avoid the collision while keeping the public column name `text`.
- **`data/` is created at startup and git-ignored.** SQLite will not create a
  missing parent directory, so `ensure_sqlite_dir()` creates it before the engine
  connects; `data/` is added to `.gitignore` so the runtime DB is never committed.
